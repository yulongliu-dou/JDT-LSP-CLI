# 调研报告：Jest spy 内置模块失败的真实原因

## 一、真正根因（之前的诊断是错的）

之前认定"**Node 新版本把 `os.homedir` / `fs.symlinkSync` 改成了不可配置**"——这个诊断**不成立**。实证如下：

| 对象 | `homedir`/`symlinkSync` descriptor |
|---|---|
| `require('os')` / `require('fs')`（原始 CommonJS exports） | `{writable:true, enumerable:true, configurable:true}` ✅ |
| `import * as os from 'os'` 在 ts-jest 下得到的 namespace 对象 | `{enumerable:true, configurable:false}`（getter 型，**不可配置**） ❌ |

两个对象**不是同一个**（`namespace === rawOs` → `false`），但 namespace 上的 getter 每次访问都转发到 `rawOs`，所以读值是一致的。

**真正凶手：TypeScript 编译 `import * as os from 'os'` 时生成的 `__createBinding` 辅助函数**：

```js
// 从 .tmp-diag 里我编译出来的实际代码
var __createBinding = (function(o, m, k, k2) {
    var desc = Object.getOwnPropertyDescriptor(m, k);
    if (!desc || ("get" in desc ? !m.__esModule : desc.writable || desc.configurable)) {
        //                                          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
        // 即使原属性"可写或可配置"，也强制覆盖为一个 getter-only descriptor ↓
        desc = { enumerable: true, get: function() { return m[k]; } };
    }
    Object.defineProperty(o, k2, desc);
});
```

这个 helper 是 TS 为了**严格对齐 ESM 的"namespace 对象只读"语义**而设计的（TS 4.5+ 起），属性被换成没写 `configurable:true` 的 getter —— JavaScript 默认 `configurable: false`。`jest.spyOn` 底层走 `Object.defineProperty`，于是报 `Cannot redefine property: homedir`。

这与 Node 版本无关，只与 `tsconfig.json` 里 `module: "commonjs"` + `esModuleInterop: true` + 源码用 `import * as` 星型导入这三者组合有关。

已验证可用（56/56 通过），但有 3 个遗留问题：

2. **mock 粒度粗**：`jest.mock('fs', …)` 把整个文件里所有 `fs.*` 调用都过一层代理（虽走 actual passthrough）。
3. **[workspaceLink.test.ts 第 17 行注释](file:///e:/LSP_Scripy/jdt-lsp-cli/test/unit/libraryProvider/workspaceLink.test.ts#L17)错归因**为"只 getter 属性"，与实际根因不符，会误导后来者。

## 三、更优方案：直接 spy `require('os')` / `require('fs')`

已用最小诊断脚本验证通过：

```ts
// eslint-disable-next-line @typescript-eslint/no-require-imports
const rawOs = require('os');
const spy = jest.spyOn(rawOs, 'homedir').mockReturnValue(tmpHome);
// 源码里 `os.homedir()` 通过 __importStar 的 getter 转发到 rawOs.homedir → 拿到 mock 值
spy.mockRestore();
```

**原理**：`rawOs` 就是 Node 单例 CommonJS exports，属性是可配置的；namespace getter 闭包捕获的 `m` 正是 rawOs，spy 改 rawOs → namespace 读到 mock。

### 三方案横向对比

| 维度 | 方案 A (当前 `jest.mock` + global hook) | 方案 D (`require()` 直接 spy) | 方案 E (依赖注入：函数接收 `cacheRoot` 参数) |
|---|---|---|---|
| 代码改动 | 仅测试层 | 仅测试层，更简洁 | 需改源码 6 处调用点 |
| 全局变量污染 | 有 | 无 | 无 |
| 跨 test/Node 版本稳定性 | 高 | 高（`require` 语义稳定） | 最高（测试不依赖 mock） |
| 可读性 | 中（需理解 hook 机制） | 高（一眼看懂 spyOn） | 高（参数化天然清晰） |
| 顺带收益 | — | — | 解锁自定义缓存目录（XDG_CACHE_HOME、daemon 多实例）、简化集成测试 |
| 风险 | mock 粒度全文件 | 需 `eslint-disable` 一行 | 改动面大，风险中等 |
